# Public church calendar adapter — prepared, not activated

This anonymous, read-only endpoint fetches the operator-configured public iCloud calendar and runs the shared curated importer. It does not use Supabase Auth, a database, staff credentials, or write access to iCloud. No deployment, project configuration, secret, or account has been changed by adding these files.

## Contract

- `GET /functions/v1/public-calendar` or `?format=json`: sanitized JSON with `source`, `updated`, `synced_at`, `valid_until`, empty `recurring`, and public `events`.
- `GET /functions/v1/public-calendar?format=ics`: sanitized calendar subscription generated by the same importer. Original event IDs, reminders, people, descriptions and source URLs are never forwarded.
- `OPTIONS`: CORS preflight. Other methods return 405; unknown/repeated parameters return 400. No request parameter or header can select an upstream URL.
- `Access-Control-Allow-Origin: *` permits public site/app reads without browser access to the original iCloud publication.
- Upstream/configuration/parse/validation failures return generic JSON HTTP 503 with `Retry-After: 60`. They do not impersonate a successful empty calendar. The clients should retain their separate curated fallback and show its actual update age.

## Bounds and privacy

`CHURCH_CALENDAR_URL` is read only by `index.ts` from the function environment. It accepts HTTPS or webcal Apple calendar publication URLs on validated `calendars.icloud.com`/`caldav.icloud.com` hosts, including numbered `pN-` hosts, and only the `/published/…/…` path form. Webcal is normalized to HTTPS. Credentials, non-default ports, query strings, fragments and redirects are rejected. Never put the actual URL in a repository file, CLI argument, response, diagnostic, or access-log example.

Fetch/read work times out after eight seconds. The streamed raw body and final sanitized output are each capped at 2 MiB. Source parsing and recurrence expansion remain bounded by the shared importer. The handler applies a second JSON field allowlist and rejects private ICS property types. It never logs source content, URLs, exceptions or upstream response bodies.

Successful sanitized results are cached in memory for at most 60 seconds, shared across concurrent requests in the same isolate. `synced_at` remains the time of the successful source read; cache hits do not restamp it. HTTP cache lifetime is the remaining portion of that minute. An expired result is not served as current when the next refresh fails. Cache is per isolate, not a global rate limiter.

## Future activation

After a separate authorized church-project setup, configure `CHURCH_CALENDAR_URL` through that project's secret/environment management UI. Do not place the raw value here. Copy the function-only section in `config.example.toml` into the approved project's `supabase/config.toml` so this intentionally public endpoint can receive requests without JWT verification. This example does not modify a live project or another function's authentication.

`deno.json` pins `ical.js` to 2.2.1 for the pure shared importer at `tools/icloud-calendar/convert.mjs`. The relative import must remain available when bundling from the repository. The entry point uses standard `Deno.serve`; no service-role key is needed. Configure a frontend live endpoint only after successful approved deployment and HTTP checks. Until then, use the existing curated static snapshot.

This feed grants no editing access. iCloud editing invitations remain controlled by the calendar owner in Apple Calendar/iCloud, separately from Creek Office accounts.

## Local verification

From the repository root, install the locked parser dependency once, then run the synthetic suite without a feed URL or upstream request:

```sh
npm --prefix tools/icloud-calendar ci --ignore-scripts
node --test supabase/functions/public-calendar/handler.test.mjs
```

Tests inject only synthetic calendars and mock fetchers: methods, CORS, URL validation, redirection/fetch/parse errors, declared and streamed size limits, fetch and body timeouts, sanitized outputs, cache truthfulness, concurrent reads and content-free errors/logs. An integration test runs the real importer through both HTTP formats, including an end-less timed event and an all-day interval. `valid_until` is the last covered church-local date; timed `endsAt` is optional when no duration is supplied, and all-day `endsAt` is an exclusive date.

Check the actual Deno entry point with the pinned function configuration:

```sh
deno check --config supabase/functions/public-calendar/deno.json supabase/functions/public-calendar/index.ts
```

This may download the pinned parser dependency but does not contact the calendar, Supabase, or any account.
