# Local office service rehearsal

This is a disposable, fictional-data development environment for the actual Postgres, Auth, REST and Storage services. It is separate from the church's hosted project. Passing it is useful evidence before hosted activation; it does not prove hosted email delivery, backups, phone installation or production operations.

The checked-in configuration was generated by Supabase CLI **2.117.0**, then limited to the services needed here. It uses API port **55321**, database **55322**, local mail inbox **55324**, and browser preview **8810**. Studio, analytics, realtime, edge runtime and optional Storage features are disabled. Auth email confirmations are enabled; mail is captured locally without production SMTP credentials.

## Prepare and start

Use a Docker-compatible runtime dedicated to this task. Keep its port forwarding on loopback; Docker VM forwarding can otherwise expose ports even when a VM has no reachable address. Use a terminal whose `DOCKER_HOST` points to that verified runtime and whose context cannot override it. Check available disk space before downloading images. No account or Supabase login is needed.

From the app repository:

```sh
python3 tools/office-local-stack/prepare.py ../office-rehearsal-stack
docker network create --opt com.docker.network.bridge.host_binding_ipv4=127.0.0.1 bcbc-office-rehearsal-loopback
supabase start --workdir ../office-rehearsal-stack --network-id bcbc-office-rehearsal-loopback --exclude realtime,imgproxy,postgres-meta,studio,edge-runtime,logflare,vector,supavisor
```

The prepare command accepts only a new directory outside this repository, verifies every migration against the reviewed manifest, then copies the six unchanged baseline files plus the seventh intake-pause migration. It refuses existing destinations. Reuse an existing verified local stack by starting it directly; do not reset it to hide failed checks. Never link this directory to a hosted project. Do not use `db push`, migration repair or a hosted connection for this rehearsal.

The current manifest uses the versions recorded during the authorized hosted application; see [the hosted history map](../office-preflight/hosted-history-map.json). A new current-baseline rehearsal copies those exact seven filenames and hashes. The preserved six-file demonstration and historical restore stack retain their original history: do not rename/reset that existing data to make it resemble this packet. Earlier service evidence remains scoped to its recorded revision.

The CLI's startup/status output can contain **local privileged keys**. Capture it privately and never paste it into logs, commits, screenshots or shared reports. Verify service health, the seven recorded migrations and actual host listeners before adding any fixtures. Published ports must bind only loopback. Review local advisors with `supabase db advisors --local --workdir ../office-rehearsal-stack`; do not omit `--local`.

## Rehearse HTTP access and browser use

The companion `tools/office-rehearsal/README.md` documents the synthetic HTTP tests, safe in-memory credential input and retained-fixture cleanup. It must run against the exact API port above and refuses hosted or LAN targets. A service-role key is used only for local fixture setup; role assertions use actual signed-in users.

```sh
python3 -B -m unittest discover -s tools/office-local-stack -p 'test_*.py'
python3 tools/office-local-stack/serve.py --stack ../office-rehearsal-stack --supabase-cli /absolute/path/to/supabase
```

Open `http://127.0.0.1:8810/admin/` and `http://127.0.0.1:8810/connection.html`. The preview fetches local CLI status in memory and serves only the browser-safe key. Production config files remain unchanged. It refuses a linked stack, unexpected API, unsafe Host header, private repository paths, traversal and symlink assets, and sends no-store responses without access logs.

The temporary `localDevelopment: true` config works only when **both** the page and API have loopback hostnames and explicit ports. Member connection origins remain exact. HTTP signed-document URLs must use the same local backend origin. The flag cannot activate on a public site and is not a production setting.

Use only clearly fictional records and ephemeral test accounts. Do not send mail outside the captured local inbox, import the ledger, reuse staff passwords or persist privileged keys. An uploaded synthetic source can be retained deliberately by record-preservation rules; the test report must say what remains.

## Stop and evidence

Stop the preview with Ctrl-C. Run `supabase stop --workdir ../office-rehearsal-stack` to stop this project's services while retaining local data. Then stop the dedicated runtime if no further work needs it. Do not use broad container pruning or delete shared volumes.

Record the app revision, CLI/runtime versions, migration hashes, service health, loopback listeners, actual HTTP assertions, browser result, advisor findings and remaining limitations. A prepared script or blank worksheet is not a completed service rehearsal. Keep fixture IDs and any required investigation data private to the disposable local workspace; shared reports contain counts and outcomes only.

The seven-file baseline pauses public profile submissions. The older 38-check HTTP signup rehearsal below was run against the earlier six-file baseline; it must not be represented as a pass against the paused baseline. Its signup scenarios intentionally fail until a separately reviewed intake-opening change exists. Do not reopen intake automatically to make the harness pass. Current pause/retained-review behavior is covered by the SQL regression tests.
